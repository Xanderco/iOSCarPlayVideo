# DashCast core bug audit, November 2026

Scope: phone video player, local video import, external display / AirPlay, the Cast main menu,
Drive tracking and scoring, and Info.plist/project.yml capabilities. Branch `claude/core-bugfixes`.
I checked the code by reading it and by running CI (Xcode 26, iOS Simulator). I had no physical device.

Status legend: **Fixed** = changed in this branch (regression test listed where possible).
**Needs device** = fixed or believed correct, but only a real iPhone, car or display can confirm it.
**Not feasible** = blocked by platform rules or needs Apple approval; left as is and documented.

## Top issues (why "most features don't work on device")

1. **Audio session never configured.** `setCategory(.playback, …, options: [.allowBluetoothHFP, .allowBluetoothA2DP, .allowAirPlay])`
   throws, because those options are only valid with `.playAndRecord`. The error was only printed, so the app stayed on
   `.soloAmbient`. As a result the silent switch muted videos, audio stopped when the phone locked, and audio did not keep
   playing over CarPlay or Bluetooth in the background.
2. **Imported local videos had nowhere to go.** `LocalVideoManager.localVideos` was saved but never shown anywhere in the UI.
   Picking a video copied it silently and nothing happened. Errors were swallowed with `print`.
3. **External display never received its own scene.** Info.plist had no `UIWindowSceneSessionRoleExternalDisplayNonInteractive`
   configuration, so iOS just mirrored the phone. The fallback (`UIScreen.didConnectNotification` + `window.screen = …`) is
   ignored in scene-based apps, and a new window was created on every scene activation.
4. **Driving score collapsed to 10.** The accelerometer started at app launch and was never stopped. Its `x` reading
   includes gravity, so a phone in a landscape mount registered "harsh cornering" (−3 points) every 0.2 s, even when no trip
   was running.
5. **Trips stopped when the phone locked.** `allowsBackgroundLocationUpdates` was hardcoded to `false`, even though the
   `location` background mode is declared.
6. **The player hid failures.** `isPlaying` was set to `true` when Play was tapped, whatever actually happened. A failed
   stream showed a spinner or a black box forever, and buffering was never shown.

## Phone player: VideoPlayerService / AutomotiveVideoPlayerView

| # | Issue | Status |
|---|-------|--------|
| P1 | Invalid audio session options for `.playback` made `setCategory` throw (see top issue 1). | **Fixed**: options `[]` (`.playback` already routes to AirPlay, A2DP and CarPlay). Test: `testAudioSessionCategoryIsAccepted` |
| P2 | Audio session was activated at app launch, which interrupted the user's music before anything played. | **Fixed**: the session is now activated in `play()` |
| P3 | `isPlaying` and `isBuffering` were set when buttons were tapped, not read from the player. | **Fixed**: both now follow `timeControlStatus` through KVO |
| P4 | `.failed` status, `failedToPlayToEndTime` and errors were ignored, with no message or retry. | **Fixed**: `playbackError` is published, and the view shows an overlay with Retry and Close. Test: `testPlayerSurfacesLoadFailure` |
| P5 | Video playback stopped in the background or on lock. Apple requires the player to be detached from its layer for background audio. | **Fixed**: `isVideoLayerAttached` toggles on background/foreground. **Needs device** to confirm audio continues when locked |
| P6 | No interruption handling (calls, Siri). | **Fixed**: playback resumes when the interruption ends with `.shouldResume` |
| P7 | No Now Playing info or remote commands, so the lock screen and the CarPlay Now Playing screen showed nothing. | **Fixed**: basic title, elapsed time and rate, plus play/pause/toggle commands. **Needs device** |
| P8 | No way to close the player once a channel was loaded. | **Fixed**: added a close (X) button and `stop()` |
| P9 | The same `AVPlayer` was attached to two `AVPlayerViewController`s (phone and external screen). Only one renders reliably. | **Fixed**: replaced with an `AVPlayerLayer`-backed view, which can share one player safely |
| P10 | `skip` and `seek` could receive NaN or negative times. | **Fixed**: clamped. Test: `testSkipTargetClamping` |
| P11 | Toggling play at the end of a video did nothing. | **Fixed**: playback restarts from 0 |
| P12 | Status label said "Audio over CarPlay" even with no CarPlay connected. | **Fixed**: the label now reflects whether an external display is connected |

| # | Issue | Status |

## Drive: DriveHomeView, DriveLocationService, DrivingScorer, permissions

| # | Issue | Status |
|---|-------|--------|
| D1 | Background location was disabled (see top issue 5). | **Fixed**: enabled only while a trip records (and only if the plist declares the mode), with the blue indicator, `.automotiveNavigation` activity and no auto-pause. **Needs device** |
| D2 | Gravity-polluted accelerometer "cornering", always on (see top issue 4). | **Fixed**: cornering = speed × GPS heading-change rate, computed only from trip samples, with no CoreMotion use. Tests: `testRawAccelerometerNoLongerPenalisesLandscapeMount`, `testLateralAccelerationFromCourse` |
| D3 | One physical brake or turn spanning several GPS samples was counted several times. | **Fixed**: a 3-second cooldown per event type. Test: `testGPSEventsAreDetectedAndDebounced` |
| D4 | The scorer used `Date()` rather than the location timestamp, so batched updates produced a wrong dt. | **Fixed** |
| D5 | `startTrip` did not reset the scorer or `lastLocation`, so the new trip was charged the distance from the previous trip's end and inherited old events. | **Fixed**. Test: `testStartTripResetsScorerAndDistance` |
| D6 | Cached, stale or inaccurate fixes (accuracy below 0 or above 50 m, or older than 10 s) were accepted, causing distance jumps and phantom speed. | **Fixed**. Test: `testStaleOrInaccurateFixesAreRejected` |
| D7 | Pause then resume added a straight-line distance between the two points. | **Fixed**: `lastLocation` is cleared on pause |
| D8 | No authorization tracking. A denied permission silently recorded nothing. | **Fixed**: `authorizationStatus` is published, with an alert that links to Settings |
| D9 | The "Tracking" chip was always green. | **Fixed**: it reflects the real state (Enable Location / Location Off / Ready / Tracking / Paused) |
| D10 | The permissions sheet had hardcoded green checkmarks, and notification permission was never requested from it. | **Fixed**: real location and notification status, with Allow or Settings buttons. The fake Motion card was removed |
| D11 | The "Always Allow: detect drives even when the app is closed" claim. | **Not feasible / not implemented**: there is no automatic drive detection (it would need `CMMotionActivityManager` plus significant-change monitoring). The copy was changed to describe what actually happens |
| D12 | The start notification said "0.1 km so far · CarDash is tracking". | **Fixed**: now "0.0 km" and "DashCast" |
| D13 | Elapsed time comes from a 1 Hz `Timer`. | OK while background location keeps the app alive. **Needs device** for a long locked trip |

## Verify on device

1. Play a stream, lock the phone: audio continues, and lock-screen play/pause works.
2. Turn on the silent switch: audio still plays.
3. Import a video from Photos: it plays at once and appears under "Your Videos". Update the app: the video still plays.
4. Connect HDMI or AirPlay-mirror to an Apple TV: the TV shows the DashCast dashboard or video, not a mirror of the phone.
5. Start a drive, lock the phone, drive about 2 km: distance and route are complete, and a normal drive scores 90 or above.
